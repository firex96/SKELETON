## 6. 코드 정리 (`/simplify`)

재사용·단순화·효율·적정 깊이 네 관점 리뷰 1회.

반영:
- 연결 실패 → 503 판정을 `ExampleWebClient` 의 private 함수에서 공용 `ApiCallException.from(cause)`(public·internal 같은 파일)로 옮겼다 — 다음 클라이언트가 복사하지 않아도 같은 규칙을 따른다. 같은 변경으로 `ApiCallException` 메시지에 하위 예외 메시지를 합치던 것도 없앴다(상세는 `cause`).
- 5xx 응답 문구를 `respond` 가 강제한다(public·internal `ErrorReason.forServerError`, batch `errorCode.message`·`details` 없음) — 어느 핸들러가 무엇을 넘겨도 내부 상세가 나가지 않는다. `handleCodedException` 은 분기 없이 예외 메시지를 넘긴다.
- 같은 몸통의 404 핸들러 둘(`NoHandlerFoundException`·`NoResourceFoundException`)을 하나로 합쳤다. `hasJacksonCause` 를 `generateSequence` 한 줄로.
- `SecurityErrorResponseWriter.write` 의 `reason` 을 non-null 로. 소셜 사용자 정보 조회 실패에도 `cause` 를 넘긴다.
- batch 조회 확장을 예외를 던지는 `requireJobExecution` 으로 좁혔다(두 호출부가 모두 `?: throw` 였다). `null` 도 「없음」으로 다룬다. 테스트에 `null` 케이스 추가.
- batch 핸들러 테스트의 반복 블록 5곳을 `bodyShouldNotContain` 확장으로 묶었다.
- `OneClassPerFileConventionTest` 의 테스트 소스셋 목록을 고정 목록에서 `src/test/<소스셋>/kotlin` 탐색으로 바꿨다(새 소스셋도 검사).
- 대조 스크립트: 파생 가능한 배열 제거, 경로 인자 일관화, 덮어쓰기 환경변수 목록에 `SIBLING_ROOT` 추가, **예약 번호표 검사**(④)와 **파싱 누락 검사**(⑤) 추가 — §3 음성 확인 4종.
- 코드표 이력 문장의 날짜 중복 제거.

건너뜀:
- batch 규약 테스트가 격리 모드 때문에 소스를 두 번 훑는 비용(수 밀리초) — 기존 main 스캔과 같은 구조.
- 공용 `ErrorResponseModel.of` 의 nullable `reason` — 이번 diff 밖의 공유 시그니처.
- 응답 계약 테스트와 핸들러 테스트의 일부 중복 — 계약 테스트가 장치 B 등록 위치라 의도한 중복.
- 원인 사슬 공용 유틸(`Throwable.hasCause`) — 새 공통 표면이 늘어난다.
- `getJobExecution` 직접 호출 금지 규약 테스트, `ErrorCode` 외부 API 플래그, 401·403 짝 단일화, 바인딩 실패 문구 — §8 후속.

`/simplify` 중 발견: KDoc 에 `src/test/*/kotlin` 을 쓰자 Kotlin 의 중첩 블록 주석으로 해석돼 ktlint 가 파일을 파싱하지 못했다 — `<소스셋>` 표기로 고쳤다.

## 8. 미결·후속 (사용자 판단 요청)

- asp-net-core 4xx 프레임워크 오류(모델 바인딩 메시지)가 기술 문구를 실을 수 있는지 — asp 는 그 레포에서 작업한다(설계 계획 §4).
- 처리하지 않는 프레임워크 예외(`HttpRequestMethodNotSupportedException` 405 · `HttpMediaTypeNotSupportedException` 415 등)가 캐치올 500 이 되는지 — 새 공통 코드가 필요하다.
- `docs/INTEGRATION_GUIDE.md` 의 경로(`/api/v1/auth/login` 등, 실제는 `/auth/login`)와 일부 메서드(`socialLoginWithToken`)가 실제 API 와 다르다 — 가이드 전면 점검.
- `/simplify` 에서 범위 밖으로 둔 것: `getJobExecution` 직접 호출 금지 규약 테스트, `ErrorCode` 의 외부 API 플래그, 401·403 코드·문구 짝의 단일화. (바인딩 실패 문구는 ④ 1라운드에서 고쳤다 — §7.)

이관 결과(2026-10-26): 위 네 건은 후속 작업 「오류 응답 정리 3차」(`error-response-residuals`)에서 사용자 결정대로 모두 처리했다 — asp 검증 문구·상태 코드, Kotlin·batch 상태 기반 응답(G016~G020), INTEGRATION_GUIDE 전면 교정, 규약 테스트·`AccessDenial`. `ErrorCode` 의 외부 API 플래그는 5xx 문장을 상태(502~504)로 고르는 방식으로 대체했다.
