### 2.2 `handler/ErrorReason.kt` (신규, 두 레포 같은 파일 — 장치 A `full` 표면)

```kotlin
package <base>.handler

import <base>.enums.ErrorCode

/** 오류 응답 `reason` 의 고정 문장. 사용자에게 그대로 보여도 되는 문장만 둔다 — 내부 상세는 로그로 보낸다. */
object ErrorReason {
    const val UNAUTHORIZED = "인증이 필요합니다"
    const val FORBIDDEN = "접근 권한이 없습니다"
    const val SERVER_ERROR = "일시적인 오류가 발생했습니다. 잠시 후 다시 시도해 주세요."
    const val EXTERNAL_SERVICE_ERROR = "외부 서비스가 응답하지 않아 요청을 처리하지 못했습니다. 잠시 후 다시 시도해 주세요."
    const val MALFORMED_BODY = "요청 본문의 형식이 올바르지 않습니다."
    const val MISSING_BODY = "요청 본문이 없습니다."
    const val INVALID_VALUE = "요청 값이 올바르지 않습니다."
    const val PATH_NOT_FOUND = "요청한 경로를 찾을 수 없습니다."
    const val TARGET_NOT_FOUND = "요청한 대상을 찾을 수 없습니다."
    const val BAD_REQUEST = "잘못된 요청입니다."

    fun invalidFormat(name: String) = "'$name' 값의 형식이 올바르지 않습니다."

    fun missingParameter(name: String) = "필수 파라미터 '$name' 가 없습니다."

    fun missingHeader(name: String) = "필수 헤더 '$name' 가 없습니다."

    /** 5xx 의 응답 문장 — 외부 API 계열 코드는 외부 서비스 문장, 그 밖은 일반 문장. */
    fun forServerError(errorCode: ErrorCode): String =
        if (errorCode == ErrorCode.EXTERNAL_API_ERROR || errorCode == ErrorCode.SERVICE_UNAVAILABLE_ERROR) EXTERNAL_SERVICE_ERROR else SERVER_ERROR
}
```

### 2.3 `handler/GlobalExceptionHandler.kt`

- `respond` 를 다음으로 바꾸고, 모든 핸들러가 이것만 부른다. 핸들러 안의 `logger.*` 호출은 지운다. 5xx 는 넘어온 `reason` 과 무관하게 고정 문장을 싣는다.
  ```kotlin
  private fun respond(errorCode: ErrorCode, reason: String, ex: Exception): ResponseEntity<ErrorResponseModel> {
      val serverError = errorCode.status >= 500
      if (serverError) {
          logger.error("{} {}", errorCode.divisionCode, ex.javaClass.simpleName, ex)
      } else {
          logger.warn("{} {}: {}", errorCode.divisionCode, ex.javaClass.simpleName, ex.message)
      }
      val body = ErrorResponseModel.of(errorCode, if (serverError) ErrorReason.forServerError(errorCode) else reason)
      return ResponseEntity(body, HttpStatus.valueOf(errorCode.status))
  }
  ```
- `handleCodedException` → `respond(ex.errorCode, ex.message ?: ex.errorCode.message, ex)`.
- `MethodArgumentNotValidException`: 필드마다 `error.isBindingFailure` 면 `ErrorReason.invalidFormat(field)`(Spring 변환 예외 문구 대신), 아니면 `필드: 검증 메시지`.
- `NoHandlerFoundException`·`NoResourceFoundException` 은 핸들러 하나(`@ExceptionHandler(NoHandlerFoundException::class, NoResourceFoundException::class)`)로 받는다. `hasJacksonCause` 는 `generateSequence(ex.cause) { it.cause }.any { it is JacksonException }`.
- 프레임워크 핸들러의 `reason` 은 기획서_public-api §3 표대로 `ErrorReason` 을 쓴다. 바뀌는 코드: `MissingRequestHeaderException` → `NOT_VALID_HEADER_ERROR` + `ErrorReason.missingHeader(ex.headerName)`, `JacksonException` → `JACKSON_PROCESS_ERROR`.
- `ConstraintViolationException`: `ex.constraintViolations.map { "${it.propertyPath.last().name}: ${it.message}" }.distinct().sorted().joinToString(", ")` — 정렬해 문구를 결정적으로 만든다.
- `MethodArgumentTypeMismatchException` → `ErrorReason.invalidFormat(ex.name)`, `MissingServletRequestParameterException` → `ErrorReason.missingParameter(ex.parameterName)`.
- `WebClientRequestException` → `respond(SERVICE_UNAVAILABLE_ERROR, ErrorReason.EXTERNAL_SERVICE_ERROR, ex)` — internal 에 같은 핸들러를 추가한다.
- public `AccessDeniedException`: 익명 `ErrorReason.UNAUTHORIZED` / 인증됨 `ErrorReason.FORBIDDEN`.

  /** 없는 id 면 JobExecutionNotFoundException(404 JOB_002). Spring Batch 6 의 getJobExecution 은 없는 id 에 EmptyResultDataAccessException 을 던진다. */

2. batch 재현 테스트부터 → batch 구현 → public → internal → SKELETON 스크립트·문서.
3. 레포마다 `./gradlew ktlintFormat` → `build` → `check`, public·internal `docker compose up -d` → `e2eTest`.
4. `/simplify` → 재검증. 장치 A·B(`--repo public`·`--repo internal`·`--repo batch`)·C(`error-code-parity.sh`, 임시 사본 음성 확인 포함), §7 재스윕.
5. public 실제 기동 스모크(깨진 JSON·`{}`·타입 불일치·없는 계정, 5xx 는 유도 경로가 없으면 생략 사유 기록).
6. ④ `cr-gate.sh code`·`runtime` + Claude 런타임 → `검증_리포트.md` → 커밋은 사용자 지시 후(형제 레포마다 기능 하나, SKELETON 은 기록·장치/문서 분리).
7. 롤백: 레포별 커밋 `git revert`. 데이터 변경 없음.
