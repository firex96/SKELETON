## 3. 브라우저 육안 확인

`local` 프로필로 8081 에 기동하고 관리자 API 로 third-party 클라이언트를, 회원가입으로 테스트 사용자를 만든 뒤 Chrome 으로 확인했다.

1. `GET /oauth2/authorize?...&state=visual-check` → 로그인 화면(`/oauth2/login`, 쿼리 없음)
2. 로그인 → 원래 authorize → 동의 화면(`/oauth2/consent?...`): 클라이언트 이름 「육안확인 서드파티 앱」, scope `openid`·`profile`·`email`, 거부·동의 버튼
3. 동의 → `http://localhost:8080/callback?code=…&state=visual-check` (받는 서버가 없어 브라우저 오류 화면 — 예상 동작)

- 소셜 로그인은 `local` 에 provider 설정이 없어(주석 처리) 실제 provider 왕복은 확인하지 않았다. 콜백의 Location·교환 계약은 provider 대역을 쓴 통합 테스트로 확인했다. 실제 provider 확인은 계정이 필요한 `SocialLoginBrowserE2ETest`(`-Pkotest.tags=browser`)로 할 수 있다.
- 로컬 DB 에 육안 확인용 클라이언트 1개(`육안확인 서드파티 앱`)와 사용자 `visual_check_user` 가 남아 있다(docker compose 로컬 DB 전용).
