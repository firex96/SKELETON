# 테스트 시나리오

- 기획서: [`public-api`](기획서_public-api.md) · [`internal-api`](기획서_internal-api.md) · [`batch`](기획서_batch.md)
- 배치 규칙: unit = `src/test/unit`(Spring Context 없음), integration = `src/test/integration`(Testcontainers), e2e = `src/test/e2e`(public·internal, `docker compose up -d`).

## 1. `ErrorCode` 불변식 — unit, 3레포 (`ErrorCodeContractTest`)

| 시나리오 | 기대 |
|---|---|
| 모든 항목의 status | 400 이상 599 이하 — 3레포 모두 `shouldBeInRange` 로 단언(batch 는 `status.value()`) |
| 구분 코드 유일성 | public·internal `divisionCode`, batch `code` 에 중복 없음 |
| 삭제 확인 (public·internal) | `INSERT_ERROR`·`UPDATE_ERROR`·`DELETE_ERROR` 가 없다 — status 200 항목이 없다는 첫 시나리오가 함께 고정한다 |

## 2. 예외 기본 코드 — unit, public·internal (`ExceptionTest`)

| 시나리오 | 기대 |
|---|---|
| `ClientBadRequestException("x")` | `errorCode == BAD_REQUEST_ERROR`, `message == "x"` |
| `InvalidRequestParameterException()` | `errorCode == BAD_REQUEST_ERROR`, 기본 메시지, `ClientBadRequestException` 의 하위 타입 |
| `ItemNotFoundException("x")` | `errorCode == NOT_FOUND_ERROR` |
| `ApiCallException()` | `errorCode == EXTERNAL_API_ERROR`, 기본 메시지 |
| `ApiCallException("x", SERVICE_UNAVAILABLE_ERROR, cause)` | 코드·메시지·cause 보존 |
| `CodedException(CONFLICT_ERROR)` (public) / `CodedException(FORBIDDEN_ERROR)` (internal) | `message == errorCode.message` — internal `ErrorCode` 에는 `CONFLICT_ERROR` 가 없다 |
| public 인증 예외 10종 | 각자 기획서 §2 의 `errorCode` (`MfaException` 은 생성자 인자) |

## 3. 응답 계약 — integration, public·internal (`ErrorResponseContractIntegrationTest`)

기존 세 시나리오(필드 노출, 본문 누락, 본문 형식 오류)는 유지한다. 추가:

| 시나리오 | HTTP | 본문 기대 |
|---|---|---|
| 검증 실패 (`@Valid` 본문) | 400 | `$.status` 400, `$.code` `NOT_VALID_ERROR`, `$.divisionCode` G011 |
| `ApiCallException(errorCode = SERVICE_UNAVAILABLE_ERROR)` | 503 | `$.status` 503, `$.code` `SERVICE_UNAVAILABLE_ERROR`, `$.divisionCode` G016 |
| `ApiCallException()` 기본 | 502 | `$.status` 502, `$.divisionCode` G014 |
| `CodedException` 직접 던짐 (public `CONFLICT_ERROR`, internal `FORBIDDEN_ERROR`) | 409 / 403 | `$.status` 가 HTTP 와 같음, `$.divisionCode` G008A / G008, `$.reason` 이 예외 메시지 |
| `ItemNotFoundException` | 404 | `$.status` 404 (기존 단언 유지) |

## 4. 핸들러 회귀 — integration, public·internal (`GlobalExceptionHandlerTest`)

| 시나리오 | 기대 |
|---|---|
| 기존 엔드포인트 전부 | HTTP 상태 단언이 바뀌지 않고 통과 (기획서 P6) |
| `ApiCallException` 엔드포인트 | 503, `$.code` 를 `INTERNAL_SERVER_ERROR` → `SERVICE_UNAVAILABLE_ERROR` 로 갱신 |
| public 인증 예외 (`Forbidden`·`Authorization`·`Unauthorized` 등 기존 케이스) | 상태·`$.divisionCode` 유지 (기획서 P7) |
| `IllegalArgumentException` | 400, `$.status` 400, `$.divisionCode` G011 |
| `NoSuchElementException` | 404 유지 |
| `NullPointerException` (엔드포인트 추가) | 500, `$.status` 500, `$.divisionCode` G010 |
| `IOException` (엔드포인트 추가) | 500, `$.status` 500, `$.divisionCode` G005 |
| `WebClientRequestException` (public, 엔드포인트 추가) | 503, `$.status` 503, `$.divisionCode` G016 |
| `MethodArgumentNotValidException` | 400, `$.reason` 이 `필드: 메시지` 조합 그대로 (기존 메시지 조합 유지) |

## 6. batch 핸들러 — unit (`GlobalExceptionHandlerTest`, standalone MockMvc + `setControllerAdvice`)

| 시나리오 | HTTP | 본문 기대 |
|---|---|---|
| `ItemNotFoundException("Product", 1L)` | 404 | `code` COMMON_002, `message` 예외 메시지 |
| `BatchProcessException("x")` | 500 | `code` BATCH_001 |
| `JobNotFoundException("sampleJob")` | 404 | `code` JOB_001, `details` `jobName: sampleJob` |
| `JobExecutionNotFoundException(7L)` | 404 | `code` JOB_002, `details` `jobExecutionId: 7` |
| `InvalidApiKeyException("Invalid API Key")` | 401 | `code` AUTH_001, `message` `Invalid API Key` |
| `ForbiddenException("내부 사유")` | 403 | `code` AUTH_002, `message` 가 `FORBIDDEN.message`, 응답 어디에도 `내부 사유` 없음, `details` 없음 |
| `InvalidJobParameterException("sampleJob", setOf("b", "a"))` | 400 | `code` COMMON_001, `message` `INVALID_REQUEST.message`, `details` `rejectedKeys=[a, b]`, 응답에 `sampleJob` 없음 |

기존 통합 테스트(웹훅·인가 경로)는 그대로 통과해야 한다.

## 7. e2e — public·internal

- 추가 시나리오 없음. `ErrorResponseFormatE2ETest`(public) 등 기존 e2e 가 그대로 통과한다(401·403 응답 형식 회귀).
