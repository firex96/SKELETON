## 5. 코드 정리

`/simplify` 1회 — 재사용·단순화·효율·적정 깊이 네 관점 리뷰.

반영:
- 외부 API 502·503 의 본문 단언이 `ErrorResponseContractIntegrationTest` 와 `GlobalExceptionHandlerTest` 에 중복 — 본문 `status` 단언은 계약 테스트(장치 B 등록 위치)에만 두고, 핸들러 테스트의 기본 502 케이스와 503 케이스의 `$.status`·`$.divisionCode` 를 지웠다(public·internal).
- internal 테스트의 `CodedException(FORBIDDEN_ERROR, …)` 메시지가 public 의 409 상황 문구를 복사한 것이었다 — 「이 작업을 수행할 권한이 없습니다」로 교체.
- `ExceptionTest` 의 항상 참인 `shouldBeInstanceOf<CodedException>()` 2건 삭제(public·internal).
- batch `JobNotFoundException.jobName`·`JobExecutionNotFoundException.jobExecutionId` — 읽는 곳이 없어져 `val` 을 지우고 생성자 인자로만 둔다(값은 `details` 에 실린다).
- batch `InvalidJobParameterException` 핸들러 로그가 `rejectedKeys` 를 다시 정렬하던 것을 `ex.details` 로 대체.
- `handleCodedException` KDoc 의 하위 클래스 나열을 「`CodedException` 하위 타입 전부」로 일반화(public·internal).

건너뜀:
- `ExampleWebClient` 가 연결 실패도 502 로 감싸므로 503 으로 나누자는 제안 — HTTP 상태가 바뀌어 이번 범위(응답 불변) 밖이다. 후속 과제.
- batch `ForbiddenException` 의 메시지 인자를 없애고 전용 핸들러를 지우자는 제안 — 응답은 같지만 ③ 승인 설계·문서(전용 핸들러 둘)를 바꾸는 변경이라 이번에 하지 않는다. 후속 과제.
- public·internal `ErrorCode.status` 를 `Int` 대신 `HttpStatus` 로 바꾸자는 제안 — `ErrorResponseModel`·`SecurityErrorResponseWriter` 까지 번지는 변경이라 범위 밖. 후속 과제.
- batch 핸들러의 `ex.message ?: errorCode.message` — 컴파일러 타입(`String?`)상 필요하고 `!!` 는 규약상 금지라 유지.
- 예외별 KDoc 의 「— 401 `UNAUTHORIZED_ERROR`」 표기 — 기존 코드 스타일(`AccountLockedException`)과 같아 유지.
- 프레임워크 4xx 핸들러가 `error` + 스택으로 로그를 남기는 것 — 이번 변경 전부터의 동작이고 기획서가 「기존 로그 유지」로 정했다. 후속 과제.

재검증 범위: 3레포 테스트·batch 핸들러·예외 변경 → 3레포 `ktlintFormat`·`build`·`check` 재실행 — 셋 다 BUILD SUCCESSFUL. 장치 A 재실행 — `SAME=38 DIVERGED=0`. 운영 응답 경로는 batch 핸들러 로그 인자와 KDoc 만 바뀌어 e2e·장치 B 는 재실행하지 않는다(응답·테스트 신호 불변).
